# DECISIONS
1. Stack fixed per brief: Next.js 15 App Router, TS strict, Tailwind, Postgres+Prisma, Auth.js, pnpm. `guionista/` is ignored (superseded).
2. Single portable .exe: built last, by wrapping the Next.js standalone output; Postgres is the system of record in dev (docker). Packaging path decided at that slice.
3. Reference is a native MFC app; hex/type tokens can't be sampled without a Windows runtime. Tokens chosen conventionally and marked unverified in SPEC.md.
4. Font: Courier Prime via local files. Name: Guionista wordmark (text only).
5. Pagination engine is pure TS in src/engine, framework-free, unit-tested with vitest.
6. Prisma pinned to v6 (stable); v8 RC is the pnpm default. Postgres 16 via docker-compose (port 54329).
7. Auth.js v5: Credentials provider + JWT sessions; passwords hashed with node:crypto scrypt (no extra dependency). No middleware (Edge can't use Prisma/scrypt); every page and API route calls auth() itself.
8. A script is one row: elements as a Json column, with an integer `rev` for optimistic concurrency (409 on stale writes; the UI stops writing and asks the user to reload).
9. The portable .exe is an Electron shell that runs the Next.js standalone server on 127.0.0.1 (random port, per-launch token cookie). Offline single file cannot depend on a Postgres server, so storage sits behind `src/lib/store.ts` with two implementations: Prisma/Postgres (server) and atomic JSON files next to the exe (desktop). Auth is bypassed in desktop mode (single local profile).
10. AI assistant (v2.5, replaces the API-key design): the panel hosts the free web versions of Claude, ChatGPT and Gemini in an Electron WebContentsView (persistent session partition, sign-in once, no API keys, no server proxy; https only, sign-in pop-ups allowed, all other navigation blocked, no preload, no access to the app server because it needs the token cookie of the default session). The view is moved/hidden over the panel by IPC (ai:show/hide) and hidden while dialogs or menus are open. "Paste into chat" copies the chosen context and pastes it with webContents.paste().
11. Dual dialogue: columns start 0.5in into the left margin, end at the right margin (3.2in each at most, 0.3in gap), so a wider margin narrows them; dialogue fills the column, character +0.9in, parenthetical +0.5in on both sides. With the caret in a speech the command pairs it with the next speech (or opens an empty right column); on an empty line it starts a new pair. The original only enables it inside a character element (strings: "Converts the character and dialogue at the insertion point to a dual column format").
12. Revision asterisks go in the left margin (per brief) at x=1.25in (scene numbers, when shown, sit left of them at 0.7–1.15in). Locked pages freeze numbers; inserted pages become 12A, 12B.
13. PDF export is produced from a server-rendered /print/[id] route (same engine, CSS inches/pt) via Electron printToPDF (desktop) or window.print (web).
14. Tooling: no Wine/poppler here; the Windows exe is cross-built and cannot be executed in this container. The same app is verified running as a Linux Electron build under xvfb.
15. electron-builder treats a folder named `app/` as the application directory and silently drops `node_modules` from `extraResources`; the Next server therefore lives in `desktop/server/` and an `afterPack` hook copies it into `resources/server`.
16. No image files anywhere (per brief): the app has a text wordmark only and the exe uses Electron's default icon (setting an exe icon needs signAndEditExecutable, which needs Wine on Linux).
17. Performance: pages before the edited element keep object identity (incremental pagination) and their text layer is memoised; off-screen pages render as empty sheets (IntersectionObserver); the ribbon is re-rendered only when its displayed state changes (handlers are resolved by id at click time); Navigator is memoised on a value-equal scene list.
18. Return key map follows the original's Screenplay element settings (read from its embedded settings with REA/strings), NOT the first brief: Scene Heading / Action / Shot → Action, Character / Parenthetical → Dialogue, Dialogue → Action, Transition → Scene Heading, General → General. Return on an empty line opens an element list (the original's "Default" SmartType session). Space before elements follows the original too: Scene Heading 24pt (2 lines), Action / Character / Transition / Shot 12pt (1 line), Dialogue / Parenthetical 0.
19. Tab: on an empty element it cycles the element list (Shift-Tab backwards, wrapping); after a Character name it opens the extension list; after a Scene Heading location it adds " - " and opens times of day; with a highlighted SmartType entry it accepts it.
20. SmartType ships with built-in lists (INT./EXT., times of day, extensions, transitions) so it works from the first keystroke; entries from the script are ranked by use; the writer can add/hide entries per script (Document → SmartType). The popup is a fixed-position list anchored to the caret (never clipped by the page).
21. Theme: one set of CSS variables (day / night / midnight) drives page, canvas, ribbon, navigator, assistant, dialogs and menus; the page always has a drawn edge; print/PDF is always black on white.
22. Screen-time bar: pages are the unit (54 rows = 1 minute); target length per script (default 90 min), Document → Target Length.
23. Launcher: electron-builder's "portable" target deletes and re-extracts the whole app (about 440 MB, thousands of files) into %TEMP% on every launch (see its portable.nsi), which makes every start slow. desktop/build-win.mjs therefore builds the exe from win-unpacked + 7-Zip + our own NSIS stub (desktop/launcher/launcher.nsi) that extracts ONCE into %LOCALAPPDATA%\Guionista\<build> and then starts the app from there. Verified under Wine (extraction + marker); Chromium 138+ does not run under Wine, so the Windows app itself remains untested on real Windows.
24. Several scripts at once (v2.5): one BrowserWindow per script (so each has its own taskbar entry and a title with the script name); the welcome page ("/") is its own window and turns into the script window when you pick something in it. Opening a script that is already open focuses its window instead (win:openScript). New / Templates open the welcome page in a new window.
25. Right margin: default 3 cm (layout version 2). Layouts saved without the version whose right margin was <= 1.2in are moved to 3 cm on load; wider margins are kept.
26. Per-element layout (Document > Page Layout > Each element): typeface, bold/italic/underline, caps (turn-on only; Scene Heading, Character, Transition, Shot and End of Act are always caps because their text is stored in capitals), alignment, left/right margin from the page edge and blank lines before. Font size and line spacing stay global: the page is a fixed monospace grid (0.6 em per character, one row per line), which the pagination, caret and PDF depend on.
27. Typing rules: first letter capitalised in Action, General, Parenthetical (inside the brackets), Dialogue, Summary and Note; choosing Parenthetical opens "( )" (existing text is wrapped) and typing stays inside the brackets; Ctrl+Backspace / Ctrl+Delete delete the word before / after the caret as in Word. SmartType lists stay closed until the first edit in a window.
28. Selection across elements (v2.6): the cursor keeps `anchor` (offset) plus `anchorId` (element) when the selection started in another element. `selection()` stays the single-element API; `span()` / `pieces()` describe a multi-element selection. Deleting one merges the head of the first element with the tail of the last (first element's type wins), like a word processor. The caret element is hidden but kept in the DOM so scrolling and popups still follow it. SmartType popups step aside while the mouse button is down (they sit above the page and would swallow the drag), and never take Shift+arrows.
29. Saved default layout (v2.6): one `layout-default.cfg` per data folder (desktop) or `User.layoutDefault` (web). It is applied server-side when a *new* script is created (`newScript: true` in POST /api/scripts); restoring a backup keeps its own layout. "Reset to original" only changes the open script; "Forget my saved default" removes the saved one.
30. Never lose work (v2.6): the shell asks each window to flush (`window.__guionistaFlush`) before closing or quitting; an engine crash restarts the engine on the same port; a renderer crash reloads the window; uncaught shell errors are logged, not fatal once started. FileStore copies the previous version to `backups/` before overwriting (max one per 5 min per script, 15 kept) and when a script is deleted. localStorage is NOT used for anything important: the origin includes a random port, so it does not survive restarts.
